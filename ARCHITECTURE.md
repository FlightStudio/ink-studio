# Architecture

## What this is

Ink Studio v2 is the editor for physical letters and postcards. This file names files and constants. Values live in code.

1. An app may import packages. A package never imports an app.
2. Dependencies point toward `packages/types`. `packages/errors` stands alone. `packages/api` may import `packages/errors`.
3. Drizzle and `pg` live only in `packages/db`.
4. Pages read through `apps/web/src/server`. Mutations go through `apps/web/src/app/api`.
5. `getSession` in `apps/web/src/server/auth.ts` is the one function the move replaces.

## Pages

A product is a `PAGE_SPECS` entry. The editor and the renderer read it and never name one. Nothing in code names a product or a page count; `packages/render/src/html/geometry.ts` reads everything from the `PageSpec`.

The page limit is `maxPages`, which a deployment sets up to `providerMaxPages`. Sides are numbered from 0. A spec whose `front` is `image` writes from side 1, and `writingSides` runs to `maxPages`.

Paper coordinates are inches from the top-left of one side's canvas, bleed included. Placed boxes, the safe zone and keep-clear zones use them. Column coordinates are inches from the top-left of the first writing side's text area and run down through every writing side, with `sideTopIn` giving each side's top. `columnBox`, `pageExclusions` and `clipToText` return column coordinates. `sidesUsed` and `overflowIn` take gap-free column inches, as print lays them out.

Exclusions are spacer floats. `pageExclusions` gives a full-width band after every writing side, down to the next side's top, so text past the last side starts in the text area of the sheet after it, and every keep-clear zone clipped to its side's text area, floating on the side its corner names; a zone inside the margin adds nothing. `exclusionFloats` turns exclusions into a zero-width spacer and a clearing float each, so exclusions on both edges keep their own tops.

## The letter document

`LetterContent` is defined once, in `packages/types/src/letter.ts`. A letter is Tiptap JSON over `letterExtensions` in `packages/render/src/schema/letter-schema.ts`, never HTML or Markdown. `@repo/render/schema` imports only `@tiptap/core`, `@tiptap/pm`, `zod` and `@repo/types`, so services and Server Components can import it.

`parseLetterContent` in `packages/render/src/schema/parse-letter.ts` is the one parser. Its zod schema is typed against `LetterContent`, builds every enum from the catalogues, refuses unknown keys, requires a UUID for every id, holds the counts to `LETTER_LIMITS`, and checks `minSides` and the front image against the letter's `PAGE_SPECS` entry. It then checks the tree against the Tiptap schema. A refusal throws.

Ids reach CSS only through catalogue lookups. Each extension's `renderHTML` reads `INK_COLORS`, `STOCK_FONTS` and `TEXT_SIZES`; a font family is `stock-<id>` or `own-<fontId>` with the stock fallback behind it. Creator-typed text never reaches CSS.

Placed elements live in the document's root attributes beside `minSides` and the front image, so one undo stack covers text and placement. `humanSeal` derives the seal from the document and the creator's own fonts; nothing stores it. `listOf` in `packages/types/src/letter.ts` joins that seal's names and the blank-letter phrases in `apps/web/src/features/fonts/font-status.ts`.

## One page

`LetterPage` in `packages/render/src/html/letter-page.tsx` is the one page component, and `LetterPageProps` is its contract: callers pass the letter, its `LetterResources`, the mode, the merge values, how many sheets to draw, the text flow and an optional handles layer. The page computes the spec, the gap between sides (`pageGapIn`), the bands, keep-clear zones, placed elements and font faces itself. It always lays out every writing side up to `maxPages`; `sheets` only decides how many paper sheets are drawn behind the flow, and the `letter-sides` box is as tall as those sheets. In print that box clips to its sheets. While editing, the column ignores the pointer and only the `letter-text` root takes it, so the column below the drawn sheets never covers what sits under the page. `elementFrame` is the one rule for a placed box's position, size and turn, used by the drawn element and by its handles. The turn is the CSS `rotate` property, so no transform animation can undo it; placed elements settle in with `scale` and opacity only. Every class the page draws has its rule in `LETTER_CSS`, so studio styles cannot change the letter; `packages/render/src/html/letter-page.test.tsx` checks it. An image front is a full-bleed first sheet and the column starts on the next side. Node components read the resources, merge values and mode through `useLetterPage`, so they render the same in the editor and the static renderer.

`LETTER_CSS` in `packages/render/src/html/letter-css.ts` is the letter's whole look, and `LetterPage` renders it itself, so the editor, the preview, the print document and the browser tests carry the same rules with nothing to import. The paper texture is the `--letter-paper-texture` custom property, which only the studio layout sets; print is plain white. One `letter-text` rule is shared by the editor root and the static root; its line height is `TEXT_LINE_HEIGHT`, which the list preview also counts lines with.

The spacer floats from `exclusionFloats` are the first children of the `letter-column` element and ignore the pointer, so empty space beside them is still text. A doodle with wrap set asks the text to flow down the wider side. `wrapExclusions` pads that footprint by `WRAP_PADDING_IN`, clips it with `clipToText`, and makes one float on the side with less room. Overlapping footprints on the same side and the same edge become one exclusion. `LetterPage` passes those floats with the page exclusions. Wrap text is one `updateElement`. Keep-clear zones are hatched only while editing. `KeepClearGuides` in the editor's handles layer gives each zone a tooltip, and a caption when it is big enough, from `KEEP_CLEAR_COPY`, which reads the spec's product. Font families are `stock-<id>` and `own-<fontId>`, and every URL in the page is `assetBaseUrl` or `stockFontBaseUrl` plus an id. A placed drawing missing from the resources throws. Apps read stock font bytes from `packages/render/fonts` by `STOCK_FONTS` file name.

`LetterPrint` in `packages/render/src/html/letter-print.tsx` is the print version: `LetterPage` in print mode with every allowed sheet, or the `sheets` it is given, and a flow built by `@tiptap/static-renderer` over `letterExtensions`. An empty paragraph, or one ending in a hard break, gets a trailing break as ProseMirror's does, so it keeps its line. `renderLetterHtml` in `packages/render/src/render-letter-html.tsx` wraps it in a full document whose page size comes from the spec.

The measure is scale-aware. `measureLetter` in `packages/render/src/html/measure.ts` is self-contained so Playwright can send it into a page, and it runs on the `letter-column` element. It divides line rectangles by the column's own scale, so `transform: scale()` and the device scale factor change nothing, and it returns gap-free column inches, counting the sheet after the last side too, so the editor and the print give the same numbers to `sidesUsed` and `overflowIn`, overflow included. `measureInputFor` builds its input from a spec and a mode.

Text that does not fit is shown, never cut. `LetterEditor` keeps the whole flow and, when `overflowIn` is above zero, draws one sheet past the last allowed side behind that text. `OverflowNotice` says how many words will not fit. The extra sheet is paper only; nothing slices the text to the page limit.

`PrintPreview` in `apps/web/src/features/editor/components/print-preview.tsx` is a full-screen `Dialog` on the desk, so Escape closes it and focus returns to its button. It draws one white sheet per side in use, each a same-origin iframe that holds `LetterPrint` with `SAMPLE_MERGE_VALUES` through a React portal, moved up to that side. The studio's desk, paper texture and keep-clear guides cannot reach the print page, and no server route renders the letter. The preview is this browser's print layout. ## How handwriting varies

`buildFont` in `packages/integrations/src/worker/font/opentype-font.ts` writes an OpenType font from glyph outlines at `UNITS_PER_EM`, with a notdef glyph and a space. A character with variants keeps its default glyph under the character's name and gets alternates suffixed alt1, alt2 and so on; only the default is in the cmap. Variants of one character run from 0 without gaps, and `buildFont` throws otherwise. `outlineOf` simplifies every polygon of a drawn or photographed cell with `simplifyLoop` from `packages/integrations/src/worker/font/vectorize.ts`, starting at `OUTLINE_TOLERANCE` and doubling the tolerance until the cell has at most `MAX_GLYPH_POINTS` points, because opentype.js measures each glyph by spreading all its points into one call. So a cell as dense as `GLYPH_LIMITS` allows still builds.

Variation lives in GSUB, written through opentype.js's own table writer, which handles every lookup this layout needs. Each stylistic set, ss01, ss02 and ss03, owns one chained-context lookup (type 6, format 3). One single-substitution lookup per variant number maps each default to that alternate; these belong to no feature and run only from the chained lookups. Per letter, a set's subtables are ordered: the last variant behind and no substitution, so the cycle wraps to the default; then each alternate behind, stepping to the next; then the default behind, stepping to the first alternate. ss02 and ss03 end with a subtable with an empty backtrack that starts the letter one or two steps in, wrapped by that letter's own variant count. Within one lookup the backtrack sees the glyphs this lookup has already substituted, which is what makes a run cycle. The backtrack is the previous glyph only, so the cycle runs through repeated letters; after any other glyph a letter starts again where its set starts.

`variantFeatureSettings` in `packages/render/src/html/letter-page.tsx` hashes the letter id with FNV-1a and picks one of the three sets. `LetterPage` puts it in the `--letter-variant-set` custom property, and the shared `letter-text` rule in `LETTER_CSS` applies it as `font-feature-settings`, so the editor root and the static root carry the same set. A letter always prints the same, and two letters differ.

Parity. `packages/integrations/src/worker/font/opentype-font.browser.test.ts` measures advances at the print device scale factor in Chromium and WebKit, as differences of widths from the start of the run, because WebKit pads a lone character's range in the middle of a run. Both engines cycle every case. Playwright's WebKit on Linux shapes with HarfBuzz as Chromium does; Safari on the iPad shapes with Core Text, which this test does not reach.

## Handwriting fonts

A handwriting font belongs to the creator who drew it. The `fonts` table stores `owner_user_id` beside `organization_id`. `FontService` in `packages/services/src/fonts/fonts.service.ts` creates a font, replaces one drawn cell, lists the caller's own fonts, reads one font and deletes it. `isOwnFont` is the one ownership rule for every write: another organization is not found, and a teammate in the same organization is refused. `listFonts` returns the caller's own fonts only. `getFont` returns the owner's cells, and nothing for anyone else.

`missingChars` in `packages/types/src/handwriting.ts` is the one rule for which required characters are still missing. It reads `HANDWRITING_GLYPHS` and treats a glyph with no strokes as missing. `REQUIRED_PUNCTUATION` adds nothing, so the sentence marks are optional, the same as the hyphen, and a skipped one is written in Caveat. A letter with variants counts as drawn when any of its variants has strokes. `missingLowercase` is the rule for a built font: the lowercase letters its `chars` lack. The upload parse thread refuses a file by the same `LOWERCASE_LETTERS`. A name has each run of whitespace, such as a pasted tab, made one space. A name over `OWNER_NAME_MAX_CHARACTERS` is then `owner_name_too_long`; an empty name or one with control characters is `invalid_owner_name`.

A font's status is worked out on every read and never stored. `byId` and `listByOwner` in `packages/db/src/drizzle/fonts.ts` left-join the asset named by `pendingFontAssetId` and return its processing as `pendingBuild`. `statusOf` in `FontService` turns that into `FontStatus`, in this order: a pending or running build is `building`; a failed one is `failed`, with its error code passed through `asApiErrorCode`; a font with a finished build is `incomplete` when `missingLowercase` finds letters and `ready` otherwise; a drawn font with neither is `drawing`, and any other font with neither is `failed`. `FontOption` and `EditableFont` carry that status, the error, the source kind, `assetId`, `pendingAssetId`, `chars` and `missingRequired`, the count of required cells a drawn font has not drawn yet (0 for other sources). The status describes the latest build attempt, so it is not the rule for writing with a font. `isUsableFont` in `packages/types/src/font.ts` is that rule: a font is usable when `assetId` is set and `missingLowercase(chars)` is empty. A failed rebuild keeps the last build in `assetId` and its `chars`, which letters keep using, so a font can read `failed` and be usable, or read `failed` and not be usable when the last build was incomplete. A page that shows a building font polls `pendingAssetId` through the asset status route. Strokes are stored in cell units (`CELL`), never screen pixels. `saveGlyph` replaces one cell inside a transaction that locks the row, so two cells saved at once both remain. Nothing here publishes a job. Pages read through `getFont` and `listFonts` in `apps/web/src/server/fonts.ts`.

A stroke with more points than `pointsPerStroke` in `GLYPH_LIMITS` is refused in `apply` before the history changes and before `glyphSaves` queues it. The cell shows `STROKE_TOO_LONG` from `apps/web/src/features/fonts/components/glyph-grid.tsx`, and Retry is not offered for it. `glyphSaves` keeps failed and newer queued strokes until a successful save. `GlyphGrid` retains their undo history, shows unsaved state, offers Retry saving, and refuses a font build while cells remain unsaved. `idle` waits for active requests; `pending` includes failed retained work.

## Tracing glyphs

`vectorize` in `packages/integrations/src/worker/font/vectorize.ts` turns a `Mask` from the lift into closed contours with no tracing dependency; potrace is GPL. Contours are in mask pixels with the origin at the mask's top-left corner and y pointing down, so pixel x, y covers the unit square from x, y and is sampled at its centre. Each contour is a list of points with an implied closing edge.

1. Marching squares over the mask padded with one clear pixel on every side, so every contour closes. A pixel is ink when its alpha is at least `INK_ALPHA`. The contour runs where interpolated alpha crosses `ISO_ALPHA`, halfway between the last clear value and the first ink value, so a hard mask's edges fall on pixel boundaries. A saddle cell joins its two ink corners when the average of its four corners reaches `ISO_ALPHA`; in a hard mask that is exactly the tie, so pixels touching only at a corner are one shape.
2. Each crossing sits on one grid edge shared by two cells, so it has exactly two neighbours, and the segments chain into loops by walking from neighbour to neighbour.
3. Ramer-Douglas-Peucker on each closed loop at `tolerancePx`, `VECTORIZE_DEFAULTS` when the caller passes nothing. The loop is split at the point farthest from its first point and the point farthest from that one, and both halves are simplified with those two points kept. A loop that simplifies to fewer than three points is narrower than the tolerance and is dropped.
4. Orientation by containment depth, counted on the unsimplified loops, which never cross: a loop inside an even number of others is clockwise and inside an odd number is counter-clockwise. Clockwise means clockwise as the mask is seen on screen with y down, which is a positive shoelace sum in these coordinates. Flipping y into font units turns outer contours counter-clockwise, the winding CFF expects, and holes the other way, so nonzero and even-odd fills agree.

`packages/integrations/src/worker/font/vectorize.test.ts` fills the contours back with the nonzero rule at pixel centres and compares them with the mask at `INK_ALPHA`, on the handwritten g from `handwrittenG` in `packages/integrations/src/worker/image/synthetic.ts`.

## Print

`PrintRenderer` in `packages/services/src/letters/letters.types.ts` is the provider the export calls, and `PlaywrightPrintRenderer` in `packages/integrations/src/worker/chromium/playwright-print-renderer.ts` implements it with Chromium. The render pool calls `connect` when `BROWSER_WS_ENDPOINT` is set and `launch` otherwise. The renderer knows nothing about letters: it takes the page's HTML, the resource map, a measure function with its input, the `sheet` size, the output and a `sides` function. Services may not import `@repo/render/html`, so the letters types declare `MeasureInput` and `LetterMeasure` structurally; the compiler links them to `measureLetter` where the worker passes it in.

- The measured root is the one `letter-column` element. `measure` runs on it in the page and `sides` runs in Node on the result; HTML without exactly one fails.
- The outside network is blocked. Requests under `LETTER_ORIGIN` are fulfilled from the resource map, keyed by full URL, with their content type and an allow-any-origin header; every other request is aborted.
- One scale factor. Each call gets its own context with JavaScript off and `DEVICE_SCALE_FACTOR`, so the measure and the pictures share one layout. The page waits for load and for its fonts before it measures or takes a picture.
- The proof is raster. `render` measures in its own page load, then screenshots each side at its `sheet` clip in whole device pixels. Sides are stacked from the top of the document with no gap.
- A PNG is one side, the one the output names.
- A PDF is a second document of one full-page image per side `sides` returns, printed at the sheet's CSS page size. With `duplex` it is padded to an even page count with a blank page.

`packages/integrations/src/worker/chromium/playwright-print-renderer.test.ts` proves these rules with hand-written HTML and the test font in `packages/integrations/src/worker/chromium/fixtures/square-a.ttf`, so integrations never imports `packages/render`.

## One letter, end to end

A letter belongs to an organization and is one `letters` row. `LetterService` in `packages/services/src/letters/letters.service.ts` creates it with the default content for its format and the untitled title for its product kind.

A save is parsed and refused when stale. `saveLetter` runs `parseLetterContent`, refuses an own font that does not exist, refuses a deleted font unless the stored letter already uses it, trims and checks the title, then saves with one conditional update that matches the expected revision and bumps it. No match is stale when the letter is still there and not found when it is not, so a stale tab never overwrites a newer save. Delete only sets `deleted_at`; a deleted letter is gone from every read.

`getLetter` returns the letter with its `LetterResources` from `letterResources` and `editable` from `letterOwnerIds`; the export reads resources through the same function. `letterResources` includes every drawing and font the letter references, deleted or not, so a letter written in a deleted font keeps it. A save refuses a drawing that is not in the organization.

A doodle or a signature is one row in the drawings table, through `DrawingService` in `packages/services/src/drawings/drawings.service.ts`. Doodles are shared with the organization. A signature is listed, renamed and deleted only by its owner. `isUsableBy` is the one rule. The mask must be an uploaded PNG of purpose mask in the same organization, its first chunk must be IHDR, and each side must stay within `DRAWING_LIMITS` in `packages/services/src/drawings/drawings.schemas.ts`. Delete is a soft delete: it sets `deleted_at`, and the library stops listing the drawing.

Placement is a doc-attribute step. `placeElement` in `apps/web/src/features/editor/elements.ts` writes the document's elements attribute, and the history plugin undoes that step along with the text. Placing a drawing also adds it to the editor's resources, so `LetterPage` can draw the mask before the next load. The library opens from the toolbar. `rasterize` in `apps/web/src/features/library/rasterize.ts` turns the strokes into the PNG mask that is uploaded before the drawing is saved.

A photographed doodle starts as an uploaded photo. Photograph in the library uploads it, asks for a lift, and watches the lift with `watchAssetStatus`. While the photo uploads and lifts, its preview shows under a status pill. When that watch turns slow it says so and offers Try again, which asks for a new lift of the same photo, and Choose another photo. Each upload, lift and watch belongs to one run; starting another run stops the watch, and an answer from an older run is ignored. The mask editor fetches that mask through the asset route and decodes it with createImageBitmap, so the canvas is not tainted. It tints the ink on the paper, offers a crop frame, and erases with the ink canvas drawing destination-out at the eraser size. The eraser cursor is that size scaled to the canvas as shown. Each local `CanvasStroke` captures its erase scale when it starts; preview, undo/redo, and PNG composition replay that scale independently of the current slider. These erase commands are not persisted. Crop gestures also retain their owning pointer and restore their starting crop on cancellation. Saving runs `composeMask` in `apps/web/src/features/library/compose-mask.ts` at the mask's own resolution, uploads that PNG as a mask, and stores the drawing with a photo source pointing at the original photo. A photo source has to be an uploaded photo in the same organization.

The library sheet is full height beside the page and a bottom sheet on a narrow screen. Its header, tabs and Draw and Photograph stay put and only the list scrolls. Each drawing is a tile of its mask tinted in ink on paper, with Rename and Delete in its menu. Rename puts the cursor in the selected name; Enter saves, Escape cancels, and both return focus to the menu button. Delete asks through `ConfirmDialog` first. The tile's menu gives focus up when its Delete opens that question, so the question holds focus and Tab stays inside it. Keep it and Escape return focus to the tile's menu button; after a delete, `ConfirmDialog`'s `finalFocus` moves it to the next tile, else the previous one, else Draw. A new drawing is named by `nextDrawingName`. Saving a drawn or photographed drawing adds it to the library and places it, or signs with it, at once. The draw and photo dialogs ask through `useDiscardGuard` before Escape, an outside press or Close throws away ink or a lifted photo, and cannot be dismissed while a save runs. Opening Draw focuses the dialog itself, so no text field brings up the on-screen keyboard. A signature is drawn in its own wider box above a signing line.

`rasterPlan` keeps a placed doodle's line weight the same however large it was drawn: it scales the stroke size by the drawn long side over the box's long side, never below `MIN_STROKE_SCALE`, and draws only the ink's own padded box at the long side's resolution. `composeMask` trims its result to the ink left after crop and erase with `inkBox`, which counts a pixel as ink from `INK_ALPHA`, so faint speckles do not keep the whole crop. It returns nothing when no ink is left. The mask editor's frame is exactly the canvas, its corner handles sit outside the clipped shade and are 44px with a coarse pointer, and Reset brings back the whole photo and all erased ink.

A placed doodle is moved, resized and rotated as one gesture. `apps/web/src/features/editor/element-pointer.ts` owns its initiating pointer and capture, ignores other contacts, and tears down listeners on finish, cancellation, capture loss, blur, or unmount. Cancellation restores the preview without committing. The handles follow the pointer in local state, and pointer up writes one `updateElement`, so undo takes the whole gesture back. Resize works in the element's own turned frame, keeps the ratio and the opposite corner, projects the pointer onto the diagonal so any outward drag grows it, and stops at a quarter inch or where the turned footprint, grown from that corner, meets the sheet's edge. Rotation snaps within four degrees of a right angle. A move keeps the turned footprint on the paper. A drag can cross onto the next side, and it stays on the last side past the end of the stack. A new doodle lands on the sheet most in view, or the nearest one, inside the margins and outside that side's keep-clear zones (`placementFor`), steps down and right of a copy already at that spot, and is selected with focus on its Move button; when it is not in view the page scrolls it to the middle. That button takes the keys: arrows move it, Shift for bigger steps, plus and minus resize, the square brackets turn it, Delete removes it and Escape puts it down; each key is one step, an arrow at a side's edge carries it to the next side, and the page scrolls to keep it and its menu in view. Handles are a finger wide with a coarse pointer, and resize cursors follow the turn. The rotate knob sits on a stem with its own icon, above the doodle, or below it when `knobSide` finds no paper above; a turn keeps the knob it started with. The desk clips the column with room around the sheet for the handles, and that room ignores the pointer. A click on blank paper or Escape puts the doodle down. Mod+Z and Shift+Mod+Z run the letter's history wherever focus is in the editor, outside inputs and dialogs. `PageMenu` places the doodle and signature menus under the turned selection, or above it near the bottom, inside the sheet. Recolour and Remove are their own steps. A doodle in a keep-clear zone is outlined in `--danger`, and its menu says what to keep clear. A signature is placed the same way and takes the same handles, keys and `ElementMenu`; the handles, the menu's label and the placement warnings name the element's kind, so a screen reader hears Move signature. The selected doodle's menu comes right after that doodle's handles in the DOM, so Tab reaches it before the next doodle.

## Ink

Every drawing is `Stroke[]` from `packages/types/src/stroke.ts`: an input, pen, mouse or touch, and points of x, y, pressure and milliseconds since the stroke began, in the drawing surface's own units. `strokeOutline` in `packages/render/src/html/ink.ts` is the one place a stroke becomes a polygon, so the browser, the rasteriser and the worker draw the same ink. It calls perfect-freehand with `STROKE_OPTIONS`, whose size it multiplies by the caller's scale, and it is the one place the pressure rule lives: a pen's recorded pressure shapes its width, and any other input ignores its pressure and has it simulated from speed. `outlinePath` turns an outline into one closed SVG path.

`InkCanvas` in `apps/web/src/features/ink/ink-canvas.tsx` is the one drawing surface, for doodles, signatures, font cells and the mask eraser. Strokes are stored in its `widthPx` by `heightPx` box whatever size it shows at: it is at most that wide, shrinks with its container at a fixed ratio, and maps each pointer through its on-screen box. It is a canvas with `touch-action: none` that reads every coalesced pointer event, feeds `pointerSession`, and fills one `Path2D` per stroke on the next animation frame in its text colour. It calls `onStrokeEnd` with every stroke and whether undo and redo can act whenever the strokes or the undone strokes change, and its ref offers undo, redo and clear. Glyph cells pass `scrollTouch`, so their canvas uses `touch-action: pan-y` from the start. A finger there is not ink until `touchPastSlop` passes `TOUCH_INK_SLOP`; until then the page can pan, and `onClaimPointer` is how the grid hears that the stroke has started. With `penOnly`, `drawsWith` turns fingers away so they scroll the page through `touch-action: pan-y`, while a pen and a mouse still draw; an Apple Pencil's own touches are held so the pen does not scroll.

`pointerSession` in `apps/web/src/features/ink/pointer-session.ts` holds the palm rules as a pure reducer. `touchPastSlop` and `TOUCH_INK_SLOP` live there. One stroke draws at a time. A pen keeps its pressure; a mouse or a finger stores `FLAT_PRESSURE`. A touch while a pen draws is ignored; once a pen has drawn in a session every touch is a palm, while a mouse still draws. A pen landing during a touch stroke drops that touch and draws. A second finger cancels the first finger's stroke, and a cancelled stroke is dropped. Undo moves the last stroke to the undone strokes, redo brings the last undone one back, and a new stroke or clear forgets them. Clear removes all.

## Ink lift

A photo of ink on paper becomes a soft alpha mask in `packages/integrations/src/worker/image/lift.ts`. `SharpImageProcessor` implements `ImageProcessor` from `packages/services/src/drawings/drawings.types.ts` with `liftInk`, which writes the mask as a PNG with black colour channels so the ink is tinted at render. `liftMask` returns the raw mask and can keep the full frame. Both go through the same decode, so every path into the lift has the same pixel cap, `maxInputPixels` in `LIFT_LIMITS`, read from the header before anything is decoded. Failures are `ServiceError("invalid_input", code)` with `photo_unreadable`, `photo_too_large` or `no_ink_found`.

The stages, in order:

1. Decode. `sharp` reads the header and refuses a photo over the cap, then applies EXIF orientation, flattens transparency onto white, shrinks to `workingLongSidePx` in `LIFT_LIMITS` without enlarging, and hands over raw RGB. Only this stage and the final PNG encode use `sharp`; every other stage is plain TypeScript over the raw buffer.
2. Lighting. A background estimate per channel (block mean, max filter, blur, bilinear upscale) divides each channel, so shadows and paper tint go to white.
3. Colour separation. Brightness is the brightest channel, so light coloured rulings and margins read as paper and dark ink of any hue stays dark.
4. Sauvola on brightness, from integral images of the value and its square, with a window that scales with the image's short side. A pixel darker than its threshold is hard ink.
5. Line removal. Run-length filtering on the hard mask, an opening with a line element in linear time: horizontal runs at least the width over `LINE_LENGTH_DIVISOR` long, then vertical runs at least the height over it, lose the pixels where the mask's thickness across the run is at most `LINE_THICKNESS_BASE_PX` plus the short side over `LINE_THICKNESS_DIVISOR`. A stroke crossing a line is thick across it, so the crossing stays. The rows go first, so a grid's intersections are thin by the time the columns are filtered.
6. Components. 8-connected components, from union-find over runs, drop when smaller than `SPECK_MIN_PX` or `SPECK_SHARE` of the image, whichever is larger, or when they touch the border and cover more than `BORDER_SHARE` of the image, which is a dark table edge around the paper. A page left with no hard ink is `no_ink_found`.
7. Soft matte. Alpha ramps with the distance below the threshold, inside a one-pixel dilation of the cleaned hard mask. A pixel that line removal or the component filter took out stays clear even inside that dilation.
8. Crop. `liftInk` crops to the ink plus a margin that scales with the image.

`liftMask` with `removeLines` off skips stages 5 and 6, so it returns Sauvola's mask with the matte; `liftInk` always removes them. The constants for each stage live at the top of the lift file. A stroke wider than the Sauvola window lifts hollow. Sauvola's threshold drops beside dark ink, so a mid-grey line breaks a few pixels either side of each stroke; a piece shorter than the run length then survives line removal. The border rule only sees a table edge whose dark band reaches the frame, because the lighting stage normalises a wide strip of table to paper. `packages/integrations/src/worker/image/lift.test.ts` scores each stage against the ground truth from `packages/integrations/src/worker/image/synthetic.ts`, which draws grids, rulings, a wavy underline, dotted i's, specks and a table around the paper, each with its own truth mask.

### One lifecycle for every generated file

A generated asset carries the job that produces it in its origin. A feature service inserts `generatedAsset` inside its own transaction, which makes the row `pending` with no bytes, and calls `publishAssetJob` only after the commit, so a message never names a row that is not there. The message's type is `assetMessageType` of the job's kind, from `packages/types/src/asset.ts`, and its data is `AssetJobMessage`, the asset's id and nothing else; `assetJobMessageSchema` in `packages/services/src/assets/assets.schemas.ts` parses it.

`runJob` in `AssetService` runs one delivery. `claim` in `packages/db/src/drizzle/assets.ts` is one conditional update that takes a pending asset, or a running one whose lease of `LEASE_MS` ran out, marks it running and counts the attempt; a redelivery of a finished asset and the loser of a race get nothing and the message is acked. The producer returns bytes, their type and a result. The bytes go to an attempt-specific storage key first. `complete` checks the running asset and owning attempt, publishes that key with the type, size and SHA-256 checksum, and returns the completed asset only when it wins. The optional `onComplete` runs only for that winner in the same transaction, so domain references commit beside `done` or not at all. Losing attempts leave unreferenced objects and cannot overwrite the winning bytes.

The error rule. A `ServiceError` of kind `invalid_input` is an input failure: the asset fails at once with that code, such as `photo_unreadable`, and the message is acked, because the same input fails again. Every other error is transient: `release` puts the asset back to pending with the error's text and the error is rethrown, so the message is nacked and redelivered. The transient failure on attempt `MAX_ATTEMPTS` fails the asset with `processing_failed` and acks instead, and a claim that finds the attempts already spent fails it the same way. `complete`, `release` and `fail` require both running status and the owning attempt. A stale failure leaves the replacement untouched and is acknowledged. The subscriber can execute overlapping attempts in one process, so fencing applies regardless of worker replica count. Drain older unfenced workers before running this publication contract.

One processor per kind, typed by `assetMessageType`. Each job kind gets one processor in `apps/worker/src/processors`, whose `type` is `assetMessageType` of that kind; it parses the message and calls `runJob` with a producer built on the worker-only provider. Services never hold a worker-only provider. `AssetLiftInkProcessor` reads the photo and calls `liftInk` on `SharpImageProcessor`. `sharp` stays external to the worker bundle. A finished lift-ink asset is servable, the same way a mask is; a raw photo is not. `requestLift` inserts that pending asset and publishes the lift-ink message only after the insert commits.

A drawn font builds the same way. `requestBuild` inserts a pending build-font asset, records it as `pendingFontAssetId`, and publishes only after that commits. A drawn font needs every required character first; a template-photo or upload font is built again from the same photo or file. A failed build stays as the pending asset, so the font reads as `failed`, and `requestBuild` simply replaces it. The last finished build stays in `fontAssetId` until the new one is done. When the job finishes, that pending asset becomes `fontAssetId` and the file's characters are stored beside it. An older build that finishes after a newer one was requested leaves the current build in place. Only the owner writes with a font. People in the same organization receive its file through `@font-face` so a letter in that hand can be read. No other organization ever does. A finished build-font file is servable the same way a mask is.

Drawing that font happens on `apps/web/src/app/(studio)/fonts/[fontId]/draw/page.tsx`, which sends any font whose source is not drawn to its font page and passes on `from` when it is a letter id. `glyphSections` splits `HANDWRITING_GLYPHS` into the needed characters, capitals and numbers, and the other punctuation, including the sentence marks, and adds the extra variants of the common letters once every needed letter is drawn. `NEEDED_COUNT` in `apps/web/src/features/fonts/font-status.ts` is that needed count. The page opens at the cell named by `glyph`, or else at the first blank needed letter, and rings it. Each cell measures its own width, so the grid fills the page at a 128 px minimum, or 160 px with a coarse pointer, and its `InkCanvas` draws at that exact size. `toCellUnits` in `apps/web/src/features/fonts/cell-units.ts` stores the stroke in the cell's own units, so the same mark on a large cell and a small cell is the same glyph. The canvas hands over each finished stroke and clears itself; the cell shows its saved strokes as SVG from the page's `GlyphHistory`. That history in `apps/web/src/features/fonts/glyph-history.ts` lives in a studio-owned font session from `apps/web/src/features/fonts/glyph-sessions.ts`. `apps/web/src/features/fonts/glyph-session-provider.tsx` preserves its queue, errors, and history through links and Back, warns on unload, and shows pending handwriting away from the grid. `MAX_SAVED_SESSIONS` bounds inactive clean sessions while pending, building, and subscribed sessions remain retained. Grid and font home share the build gate; completion updates an active home but cannot redirect an unmounted grid. This session is in memory and supplies no cross-tab revision contract. It records each stroke and each clear as one change to one cell, keyed by character and variant, so Undo, Redo, Meta or Control+Z, Shift+Z, Control+Y and a two-finger tap walk back across cells in order, and the cell Undo would change is ringed. `useTwoFingerTap` listens on the grid and requires eligible drawing-area contacts, excluding headings and controls. A cell at `GLYPH_LIMITS` takes no more strokes and says how to start again. Every change sends that cell's whole strokes through `glyphSaves`, which keeps one save in flight per cell and then sends only the latest, so a burst ends with the server holding the last state. A failed save keeps the newest strokes and undo history, shows unsaved state under the cell, and offers Retry saving. Failed cells remain pending until successfully saved. Before the first pen stroke a finger on a cell can pan the page, and becomes ink only after `TOUCH_INK_SLOP`. After the first pen stroke on the page every cell is `penOnly`, so fingers scroll and do not draw. While more than one finger is down, and until the next single touch starts, `useTwoFingerTap` holds its several-fingers ref, and the grid drops every touch stroke that ends then, so a two-finger tap or pinch across two cells leaves no ink and the tap's undo stays the only change. `apps/web/src/features/fonts/glyph-build-gate.ts` blocks building while a stroke is active and freezes drawing/history actions through the build request. Build my font waits for every save, refuses a build while failed cells remain pending, asks for the build and opens the font page with `from`; a refused or lost request ends Starting… and shows `buildMessage`. `glyphSaves` always settles `idle`, even when a failure handler throws. `specimenWords` finds each glyph's ink width with a loop, so a glyph at `GLYPH_LIMITS` renders. The header pins to the top over a desk-coloured band, so cells never show above it. `StrokeSpecimen` writes the specimen line from the drawn strokes with the builder's side bearing, cycling a letter's versions, and draws the rest in grey Caveat. The toolbar's My handwriting group comes from `fontMenu`. A font that `isUsableFont` passes is a choice, shown in its own font; choosing one adds that file to the letter's resources, and the page shows it at once. A drawn font still being drawn says how many required letters are done from `missingRequired` and continues on its draw page, or says Ready to build once none is missing; a font building, failed or incomplete opens its font page. Make your handwriting and Manage handwriting close the group. Every entry is a select item, and each link carries `?from` with the letter. When the editor opens with `?font` naming a usable font, `fontOfferFor` in `apps/web/src/features/editor/offered-font.ts` asks once, through `FontOffer`, whether to write the letter in it, and stays quiet when that font is already the letter's `defaults` or an ink mark, when the font is missing or not usable, or when the letter is read-only. Use it on a letter that already has text is `writeLetterIn`, one undo step. Use it on a blank letter sets that font on `defaults` and calls `edited`, and Undo and Redo put that default back when the history stack is empty. Both answers drop `?font` from the address. A missing letter calls `notFound`, and `apps/web/src/app/(studio)/letters/[letterId]/not-found.tsx` is that page.

Every fonts page builds its links with `apps/web/src/features/fonts/font-links.ts`. Every font has one home, `apps/web/src/app/(studio)/fonts/[fontId]/page.tsx`, which renders `FontHome`. `FontHome` keeps one status region mounted that says `fontAnnouncement`, and renders its view keyed by status and build, so a refresh that brings a new status starts the view afresh. The heading is `fontHeading`. After Build my font or Try again, each new view moves focus to its heading while focus was lost, until the build settles. The building pill is hidden from assistive tech, so the region is the one status. A building font is watched by `useAssetWatch`. `watchAsset` in `apps/web/src/lib/asset-watch.ts` is the one asset poller in the app, for font builds, proofs and lifts: it reads at once and then on `pollDelay`, starts the next read only after the last one answered, passes on only changed readings, turns slow after `SLOW_AFTER_MS` and stops on a confirmed completed/failed job, disposal, or a permanent read denial. `AssetReadResult` separates connection/access problems from server job state. Transient read failures preserve the last status and keep polling with capped back-off; a recovered read clears the issue even when its status is unchanged. `apps/web/src/components/shared/asset-watch-notice.tsx` supplies recovery notices to fonts, proofs, and lifts; Check again resumes reading the same asset, preserving its last state. Authentication, permission, and missing-resource responses stop observation with an actionable notice. A font page refreshes only for a confirmed terminal job state; transport trouble never creates a replacement processing job. For a settled font build the page then refreshes. Opening the page again watches the same pending asset, so a build is picked up after a reload. Slow offers Try again, which asks for a new build. A drawing font counts its letters with `lettersDrawn` from the live glyph session when that session exists, and the home refreshes when that font's pending flag clears. The list in `apps/web/src/features/fonts/components/font-list.tsx` does the same through `useExistingGlyphSnapshot` only when `find` already holds the session. A drawing font with every needed letter offers Build my font, which asks for the build the same way, with Keep drawing beside it. A failed font reads its error code through `failureOf`: a photo problem offers Photograph again, a file problem Choose another file, a drawn font missing letters Draw them, and anything else Try again. An incomplete font names the blank lowercase letters. A ready font shows the specimen in its own face, the seal line and what Caveat fills in, and its main button creates a letter through `fontId` on `CreateLetterRequest`, which `creatableFont` allows only for the caller's own finished font, and opens that letter with no `font` query. The back link to the letter in `from` still carries `?font`. A letter that cannot be started says so under the button. A missing font, including its draw page, calls `notFound`, and `apps/web/src/app/(studio)/fonts/[fontId]/not-found.tsx` is that page. `fillsInPhrase` names a whole missing group, lists a few missing members, or, when most of a group is missing, names the group with the few that were drawn. Delete asks first through `ConfirmDialog` with `DELETE_NOTE`, on the home and in the list. The list in `apps/web/src/app/(studio)/fonts/page.tsx` counts each drawing font's drawn letters in parallel, shows method and status, a specimen for usable fonts, and watches building rows.

`apps/web/src/app/(studio)/fonts/new/page.tsx` fills the seal name from the first word of the user's name (`sealNameFrom`) and keeps the three method cards disabled until there is a name. Write it here creates a drawn font and opens the draw page; Write on paper opens the template with the name and `from`; Use a font file opens `FontUploadDialog`, whose picker waits for the own-handwriting checkbox. `startFont` uploads the photo or file, creates the font, and only then deletes the font it replaces, so retrying from a failed font leaves one font. Every picker clears its value after reading, so the same file can be chosen again. The template offers Take photo only when `useCoarsePointer` is true, since a desktop picker ignores `capture`. The template takes the name from `?name` through `defaultSealName`: the typed name cleaned by `cleanOwnerName`, whole, or else `sealNameFrom` the account. The cards, the upload buttons and the seal line all use `cleanOwnerName`, which collapses spaces the way `parseOwnerName` does. The seal line under the name is not live. Upload and create failures read through `uploadMessage` and `createMessage`.

Variants are alternates. A drawn cell is keyed by character and variant, below that character's `variants` in `HANDWRITING_GLYPHS`. `lettersOf` in `packages/integrations/src/worker/font/opentype-font.ts` sorts each letter's outlines by variant and numbers them again from 0, so a blank or cleared cell leaves no gap and the next variant becomes the letter. Every variant after the first becomes an alternate glyph that the GSUB lookups cycle through. The straight quotes also answer for the curly ones: `GLYPH_ALIASES` gives the `'` glyph the code points of both curly single quotes and the `"` glyph both curly double quotes, unless the font draws them itself. `withAliases` adds them to `chars`, so the seal counts a curly quote as handwritten. An upload keeps its own curly quotes, so the straight ones stand in only for the curly quotes the file lacks.

A photographed template builds at once. The printable page is `apps/web/src/app/(studio)/fonts/template/page.tsx`. Its corner marks are black SVG shapes, not CSS backgrounds, because a browser prints backgrounds white unless background graphics is turned on; the top-left mark's notch is cut out of its path. Its cell borders, guide lines and labels are light cyan, so the lift keeps the handwriting and drops the printed template; the baseline is drawn in the border cyan, darker than the other guides, and cell labels use `glyphLabel`. On screen `TemplatePreview` scales the sheet down to the page width; in print every other element is hidden and the sheet's ancestors lose their spacing, so the sheet fills one page. `readTemplate` in `packages/integrations/src/worker/font/template.ts` finds the four marks, puts them in clockwise order, and tries each as the top left: it maps the page onto the photo and checks the inner corner of every mark, and the top left is the one whose inner corner is empty while the other three are solid, by at least `NOTCH_CONTRAST`. Then it reads each cell. A printed label can photograph dark enough to read as ink, so a mark that lies wholly inside the label corner, sized by the label entry in `HANDWRITING_TEMPLATE`, is dropped; a pen stroke that reaches outside that corner is kept. The sheet places its labels from the same setting. A photo without those marks is refused with `template_markers_not_found`, whose message says how to take the photo again. `fromTemplatePhoto` scales both axes of a cell by its mask height, so letters keep their width. Blank cells make no glyph. A photo where every cell is blank is refused with `no_ink_found`; a font that comes out missing lowercase letters still builds and reads as `incomplete`. `createFont` with that photo requires the photo to belong to the same organization, and it asks the worker to build before it returns.

An uploaded TTF or OTF builds the same way. `createFont` accepts only a font file from the same organization. The worker parses that file in a thread limited to 5 seconds and 256 MB, rebuilds a new font from its outlines inside the thread, and only the rebuilt bytes leave it. The uploaded file is never served. A file that cannot be read, that takes too long, or that is missing lowercase letters fails the build.

The sweep. The `sweep` processor calls `sweep` on `AssetService`, which reads `stale` work and republishes every pending asset untouched for `STALE_PENDING_MS` and every running asset past its lease, so a publish lost after a commit or a worker that died mid-job is picked up again. Only the standard pool takes `sweep` and only it publishes the timer: when `SWEEP_EVERY_MS` is set, `main` publishes `sweep` on that interval, and the render pool, whose subscription never receives `sweep`, publishes nothing. `pnpm jobs:sweep` runs `tools/dev/sweep.ts`, which publishes one `sweep` by hand.

## Moving into project-post

Shared packages are shaped so the move is a folder merge. The plan is `PLAN.md`.

`packages/services/src/queue` and the Pub/Sub classes in `packages/integrations/src/shared/gcp/pubsub` are v2's copies of project-post's and are dropped on the move. The render pool's filter moves from `tools/docker/pubsub-entrypoint.sh` into project-post's entrypoint and its Terraform subscriptions.

In production Cloud Scheduler publishes `sweep` to the jobs topic every minute with the `type` attribute set, and `SWEEP_EVERY_MS` stays unset, so one schedule sweeps however many workers run.

The `assets` table extends the assets outline in project-post's schema file: it adds `purpose`, `filename`, `uploaded_by_user_id` and a `job` jsonb column, makes `source` the `asset_source` enum where the outline has a varchar, and adds `assets_origin_check`, which ties an uploaded source to a purpose and no job. The schema file gains these on the move.

The real bucket needs a CORS rule allowing GET from the platform origin with the `Content-Type` header, because the browser follows the redirect to GCS from the editor. The web and worker service accounts need `roles/iam.serviceAccountTokenCreator` on themselves to sign URLs.

## Correctness regression coverage

`apps/web/e2e/harness.ts` selects Chromium or WebKit with `E2E_BROWSER`; CDP pen/touch cases remain Chromium-only. Set `WEB_BASE_URL` to a host reachable by the browser container and configure the matching platform origin. Browser editor tests use a secure context so pointer APIs and UUID generation match production; `E2E_IGNORE_HTTPS_ERRORS` opts into a local test certificate. `apps/web/e2e/recovery.e2e.ts` exercises navigation, lost acknowledgements, and conflict choices against the real save endpoints. Unit regressions cover save sequencing, canonical comparison, polling recovery, gesture ownership, and erase replay. Database/service regressions hold and reclaim worker attempts and verify publication and side effects. `apps/web/e2e/proof-fonts.e2e.ts` covers displayed font bindings and recovering observation of the same export. Browser checks cannot establish physical Pencil latency, palm rejection, or iPad keyboard behaviour.
